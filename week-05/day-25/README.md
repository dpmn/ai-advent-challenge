# Неделя 5 — День 25. Мини-чат с RAG + памятью (production-like)

## Задание

**Реализуйте чат, который:**
- хранит историю диалога
- при каждом новом вопросе ищет контекст в базе через RAG
- отвечает с учётом найденной информации
- всегда выводит источники

**Усиление:**
- добавьте “память задачи” (task state):
  - что пользователь уже уточнил
  - какие ограничения/термины зафиксированы
  - что является целью диалога
- task state должен формироваться автоматически на основе текущего диалога

**Проверьте:**
- на 2 длинных сценариях по 10–15 сообщений
- что ассистент не теряет цель и продолжает выдавать ответы с источниками

**Результат:**
- Мини-чат с RAG + источниками + памятью задачи

## Реализация

### Модифицирован: `agents/jarvis_memory.py` (TaskContext)
- Добавлен `extract_and_update()` — вызывает дешёвую LLM (Qwen3-30B-A3B) после каждого ответа, извлекает структурированное состояние задачи: goal, constraints, terms, last_focus, progress
- Улучшен `to_prompt_block()` — рендерит списки и словари читаемо
- Добавлены `TASK_STATE_KEYS` — словарь с описанием полей
- Добавлен статический `_try_parse_json()` — парсинг JSON с fallback

### Модифицирован: `agents/jarvis.py` (JarvisAgent)
- Добавлен `_update_task_state()` — обёртка над `extract_and_update()`, вызывается после каждого успешного ответа в `chat()` (кроме команд)
- Task state автоматически сохраняется в БД через `_save_memory_state()`
- State инжектится в следующий системный промпт вместе с остальной памятью

### Новый файл: `week-05/day-25/test_chat.py`
- Тест с 2 сценариями по 12 сообщений
- Проверяет: сохранение цели (goal), извлечение ограничений, наличие источников/цитат в ответах RAG
- Выводит task state после каждого сообщения

### Модифицирован: `ragger/document_loader.py`
- Добавлена загрузка `ragger/*.py` (кроме `__init__.py`) в индекс — **docstring-и** (как для agents/*.py), а не полный код. Это даёт чистый русскоязычный текст для семантического поиска.

### Модифицирован: `ragger/embedder.py`
- Модель эмбеддингов по умолчанию: `Qwen/Qwen3-Embedding-0.6B` → `openai/text-embedding-3-small` (1536-dim)

### Модифицированы docstring-и в `ragger/` (для улучшения семантического поиска)
- `chunking.py`, `indexer.py`, `embedder.py`, `search.py`, `answer.py`, `reranker.py`, `document_loader.py` — добавлены русские module-level docstring-и и расширены docstring-и функций

### Модифицирован: `ragger/reranker.py` (исправлен баг)
- `_parse_scores()` — регулярка `r"[\d.]+"` захватывала `.` как число → `float(".")` падало. Исправлено на `r"\d+(?:\.\d+)?"` с валидацией

### Модифицирован: `ragger/search.py` (устойчивость)
- `RagPipeline.run()` — `llm_rerank` обёрнут в try/except, при падении реранкера возвращаются threshold-отфильтрованные чанки

### Модифицирован: `agents/jarvis.py` (RAG-режим)
- **Убран дублирующий LLM-вызов**: `generate_answer()` уже выдаёт готовый ответ с источниками. При `rag_enabled=True` ответ RAG используется напрямую как финальный, без повторного прогона через основную LLM
- Увеличен `rag_top_k_before` с 10 до 15, `rag_top_k_after` с 5 до 8
- Режим по умолчанию: `hybrid` → `threshold` (реранкер плохо ранжирует русские запросы к коду)

### Модифицирован: `agents/jarvis_session.py`
- Обновлены значения по умолчанию для RAG-параметров в `create_session()`

### Пересобран FAISS-индекс
- `python3 ragger/pipeline.py` — перегенерированы оба индекса (fixed + structural) с новой моделью эмбеддингов
- Размерность векторов: 1536
- Источников в индексе: 47 (docstring-и из ragger/*.py) vs было 40

## Архитектура

Каждый user message → RAG-поиск (FAISS → threshold → rerank) → генерация ответа с источниками → LLM-экстракция task state → сохранение в БД → следующий запрос использует обновлённый state

Используемая модель для экстракции: `Qwen/Qwen3-30B-A3B` (дешёвая, 512 max_tokens)

## Выводы по результатам тестирования

### Что работает хорошо

1. **RAG-ответы с реальными источниками** — по вопросам про чанкинг, FAISS-индекс и реранкинг ответы содержат корректные ссылки на `ragger/chunking.py`, `ragger/indexer.py`, `ragger/search.py`, `ragger/reranker.py`. Цитаты дословные, chunk_id настоящие.

2. **Pre-verification + fallback на main LLM** — out-of-domain вопросы (погода, Гагарин) корректно отсекаются RAG-верификатором и передаются основной LLM, которая отвечает из общего знания без ложных источников.

3. **Мета-вопросы** — "О чём мы говорили?" обрабатывается через историю диалога, а не через RAG, и выдаёт связный пересказ.

4. **Task memory** — goal, last_focus и progress автоматически заполняются и эволюционируют по ходу диалога.

### Что требует доработки

5. **FAISS-ранжирование** — вопрос "Какие модели используются для построения эмбеддингов?" нашёл `ragger/chunking.py` (score 0.43) выше `ragger/embedder.py` (score 0.39) и ответил про чанкинг, а не про модели. `text-embedding-3-small` даёт низкие scores для русских запросов к технической документации.

6. **Goal persistence** — при отвлекающей теме (погода, Гагарин) goal пропадал из task context. Пофиксено: при смене темы goal сохраняется, обновляется только last_focus.

7. **Progress перезаписывался** — при возвращении к теме LLM в extract_and_update иногда перезаписывала progress вместо дополнения. Пофиксено: защита от сокращения progress.
