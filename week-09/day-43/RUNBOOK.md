# Runbook: живой routing между моделями

Слабая модель работает на ноутбуке (Ollama, RTX 3060), сильная — на арендованной
ВМ immers.cloud, поднятая **сервером** и проброшенная ssh-туннелем. Отличие от
дня 42 принципиальное: там был офлайн-батч по заранее известному списку, здесь
заранее неизвестно, какие товары и какие поля уйдут наверх — это решают
эвристики по ходу прогона.

Порядок такой, что GPU арендуется **после** того, как всё, что можно проверить
без неё, проверено.

---

## 0. До аренды (бесплатно, локально)

```bash
cd week-09/day-43

# выборка 22 товара: 8 корректных / 6 пограничных / 8 шумных
../../.venv/bin/python scripts/pick.py

# арифметика отчёта на синтетике: настоящие ответы 0.6B и 14B из дня 41,
# выдуманные logprob-ы. Проверяется, что шесть политик считаются.
../../.venv/bin/python scripts/mock_route.py
../../.venv/bin/python scripts/report.py \
  --runs results/mock_route.jsonl --anchor results/mock_anchor.jsonl \
  --out results/mock_report.md

# сухой прогон: слабая модель и эвристики живьём, эскалации нет
../../.venv/bin/python scripts/route.py --no-escalate
```

Сухой прогон отвечает на главный вопрос до аренды: какая доля товаров вообще
дойдёт до сильной модели. Если эскалируются все, routing выродится в «всегда
14B плюс накладные расходы», и это надо знать до того, как включён счётчик.

Слабая модель требует поднятого Ollama с `qwen3:0.6b`. Проверка:

```bash
curl -s http://127.0.0.1:11434/api/tags | grep qwen3:0.6b
```

## 1. Поднять ВМ

Та же конфигурация, что в дне 42: **RTX 4090 24 ГБ**, 86,74 ₽/ч, образ голый
(torch не предустановлен). 14B в 4-bit NF4 занимает ~23 ГБ на батче 8; сервер
отвечает по одному запросу, запас есть.

```bash
scp -i immers/<ключ>.pem -o IdentitiesOnly=yes scripts/bootstrap.sh ubuntu@<IP>:~/
ssh -i immers/<ключ>.pem -o IdentitiesOnly=yes ubuntu@<IP> \
  'chmod +x ~/bootstrap.sh && setsid nohup ~/bootstrap.sh </dev/null >~/bootstrap.log 2>&1 &'
```

Следить: `grep -E "^=== " ~/bootstrap.log`. Ориентир по дню 42 — 2,5 минуты
от чистого образа до скачанных весов.

---

## 2. Забросить сервер и запустить его

Раскладка плоская: `serve_big.py` ищет `schema.py` сначала рядом с собой.

```bash
scp -i immers/<ключ>.pem -o IdentitiesOnly=yes \
  scripts/serve_big.py ../day-41/scripts/schema.py ../day-41/schema.json \
  ubuntu@<IP>:~/day-43/

ssh -i immers/<ключ>.pem -o IdentitiesOnly=yes ubuntu@<IP> \
  'cd ~/day-43 && setsid nohup .venv/bin/python serve_big.py --model ~/qwen3-14b \
   </dev/null >~/serve.log 2>&1 &'
```

Готовность: `grep "модель готова" ~/serve.log`. Загрузка 4-bit занимает
около минуты.

Сервер слушает **loopback ВМ**, наружу не выставляется. На ноутбук порт
приходит туннелем:

```bash
ssh -i immers/<ключ>.pem -o IdentitiesOnly=yes -N -L 8000:127.0.0.1:8000 ubuntu@<IP>
```

## 3. Дымовой прогон

```bash
curl -s http://127.0.0.1:8000/health
../../.venv/bin/python scripts/route.py --limit 1
```

Что проверяем в первую очередь: **ответ сильной модели — чистый JSON в ~50
токенов**. Если пришло 2000 символов с рассуждениями, значит `enable_thinking`
не погасился, и весь прогон будет мерить настройку шаблона, а не модель —
ровно то, на чём сгорел baseline дня 41.

## 4. Якорь «всё на сильной» (за кадром)

```bash
../../.venv/bin/python scripts/anchor_big.py
```

22 товара батчами по 8, ~30 секунд GPU. Даёт верхнюю границу качества и,
что важнее, ответы 14B **по всем полям** — без них не пересобрать ни случайную
эскалацию, ни статичный раздел, ни другой порог.

---

## 5. Живой прогон (в кадре)

```bash
../../.venv/bin/python scripts/route.py
```

По каждому товару в логе: ответ слабой модели, пополевая уверенность,
сработавшие эвристики, эскалированные поля, ответ сильной и что изменилось
против эталона. `--pause 1` растягивает вывод, если на видео он идёт слишком
быстро.

---

## 6. Отчёт (в кадре, GPU уже не нужен)

```bash
../../.venv/bin/python scripts/report.py
```

Считает routing против шести политик, раскладывает эскалацию по эвристикам
(исправлено / испорчено / без изменений), разворачивает порог в кривую и
сверяет живые ответы 14B с дампом дня 41.

---

## 7. Погасить ВМ

Сразу после прогона. Данные уже локально: `results/route.jsonl`,
`results/anchor_big.jsonl` и меты к ним — всё остальное считается офлайн.

## Грабли

- **Туннель отваливается** — клиент отдаёт `сильная модель недоступна`, прогон
  останавливается с кодом 2, а не пишет половину результатов молча.
- **Ollama выгружает модель** между запусками (`keep_alive` по умолчанию 5 минут).
  Первый вызов после паузы занимает ~13 секунд вместо 1,7 — это загрузка, а не
  медленная генерация. Перед съёмкой стоит сделать один прогрев `--limit 1`.
- **`think: false` обязателен на обеих сторонах.** У слабой он зашит в
  `small.py`, у сильной — в `serve_big.py`. Ни там, ни там его нельзя
  «временно» отключить: сравнение сразу перестанет быть сравнением моделей.
