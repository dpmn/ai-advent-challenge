## 1. Что делаем

**Задача под файнтюн:** название карточки маркетплейса → строгий JSON атрибутов
(extraction + классификация в одном).

**Домен:** косметика, бытовая химия и смежное (расходники для бьюти-мастеров, дезинсекция,
уходовая «аптечка») — то, что реально есть в выгрузке.

**Почему здесь файнтюн, а не промпт и не RAG** — три механизма, все измеримы:

1. **Нормализация единиц.** `"1,3 л"` → `1300 ml`, `"100 гр"`/`"0.1 кг"` → `100 g`,
   `"2 шт по 300 мл"` → `volume=300, pack_count=2` (не 600).
2. **Закрытые словари.** `category` и `form` строго из списка; базовая модель выдаёт свободный текст.
3. **Отказ от галлюцинаций.** Бренда нет в строке → `brand: null`. Мелкие модели выдумывают.

Плюс экономический аргумент: прогон по миллионам карточек локальной 14B после тюна
дешевле облачного API на порядки.

**Целевая модель:** `Qwen3-14B` — сильнейший открытый вариант по русскому в этом размере,
есть запас на разбор неоднозначностей.

**Где тюним (когда дойдёт очередь):** immers.cloud, RTX 4090 24 ГБ, QLoRA 4-bit.
День 42 отдан другой теме (оценка уверенности и контроль качества инференса),
так что сам прогон обучения сдвигается на более поздний день недели.

- Покрытие: 1158 строк с объёмом/весом, 428 с pack-паттерном, ~40% названий обрезаны.

### Классы сложности в реальных данных

Всё найдено в выгрузке, не выдумано:

- **Что в кавычках** — главная неоднозначность:
  - `"Пепельный блонд" Оттеночный бальзам, 300 мл` → shade, не brand
  - `"Золушка" средство для прочистки труб, 1 л` → brand
  - `"BIELITA COLOR" тон №05.2 Баклажан (Белита-М)` → line в кавычках, **brand в скобках в конце**, shade = `05.2 Баклажан`
- **Транслитерация бренда:** `Cif`/`Сиф`, `Domestos`/`Доместос` — свести к одной форме.
- **Коды оттенков:** `Koleston Perfect 9/81`, `Color Touch 66/07`, `10.012`, `6,4`, `3,51`.
- **Множественные объёмы:** `Шампунь 75мл+маска 75мл+сыворотка 50мл`, `2 шт*500 мл`,
  `100 мл + оксид 6% 100 мл`.
- **Объём без единицы:** `Фитол-1 крем ... 75,0`.
- **Обрезанные названия** (~40%): `"...для сухи"`, `"Illumina Color 7/"`, `"(Бел"`.
  Модель не должна дописывать — прямой тест на галлюцинации.
- **Мусорные префиксы:** `!`, `! !`, `!$!`, `(`, `)`, `!ЛИКВИДАЦИЯ!`, `!0011 /`.
- **Near-дубли пачками:** `"Крем-спрей Сиф чистящий 500 мл, набор: N штук"` ×7,
  `Domestos ... 750 мл, набор: N штук` ×5, `"Крем от витилиго..."` ×6 (разные url).

## 3. Схема выхода — 9 полей

| поле | тип | пример |
|---|---|---|
| `category` | закрытый словарь + `прочее` | `шампунь`, `чистящее_средство` |
| `brand` | string \| null | `Белита-М` |
| `line` | string \| null | `BIELITA COLOR` |
| `volume` | `{value:number, unit:"ml"\|"g"\|"pcs"}` \| null | `{"value":1300,"unit":"ml"}` |
| `pack_count` | int ≥1 \| null | `5` |
| `form` | закрытый словарь \| null | `гель`, `крем`, `спрей`, `порошок` |
| `purpose` | array из закрытого словаря \| `[]` | `["против_перхоти"]` |
| `shade` | string \| null | `05.2 Баклажан` |
| `is_set` | bool | `true` |

**Правила разметки:**

- `is_set=true` (набор из **разных** продуктов) → `volume`/`pack_count` заполняем
  только если однозначны для набора целиком, иначе `null`.
- Единица не указана (`"75,0"`) → `volume: null`.
- Название обрезано → заполняем только то, что видно. Не дописываем.
- Мусорные префиксы игнорируем, в поля не тащим.
- `volume` всегда нормализован: `л→ml ×1000`, `кг→g ×1000`.

**Таксономия** финализируется на шаге 1 по фактическому распределению пула:
узлы с ≥15 примерами, остальное в `прочее`. Ориентир 18–20 узлов.
Список показывается пользователю до разметки.

## 4. Датасет

- **Объём: 500** — 400 train / 100 eval. Попадаем в лекционный коридор 100–1000,
  ~25 примеров на узел таксономии, риск оверфиттинга снижен.
- **100% реальных данных.** Задание требует минимум 20% — синтетика не нужна вообще.
- **Дедупликация:** группировка по нормализованному ключу (снят pack-хвост, мусорные
  префиксы, регистр, схлопнуты пробелы). Из группы максимум 2 варианта.
- **Group split, а не построчный.** Near-дубли не должны разъезжаться между train и eval —
  иначе утечка и завышенные метрики. Стратификация по `category`.
- **Eval преимущественно из файла-2000** (~60 из 100) — там есть url, спорный бренд
  можно разрешить, открыв карточку. Побочный плюс: eval из другой выборки = та самая
  проверка на оверфиттинг из лекции.

## 5. Разметка и контроль качества

Три слоя:

1. **Черновик** — все кандидаты (~600, с запасом на отбраковку) через `MiniMax-M2.5`
   (Cloud.ru), temperature 0, тем же system-промптом, что пойдёт в датасет.
2. **Программные инварианты** — автоматическая отбраковка:
   - `brand`/`line`/`shade` обязаны быть подстроками входа (case-insensitive) → ловит галлюцинации
   - `category`/`form`/`purpose` ∈ словарь
   - `volume` сверяется с regex-находкой во входе, с учётом нормализации `л`/`кг`
   - `pack_count > 1` только если во входе есть pack-паттерн
   - парсится как JSON, все 9 ключей, типы верны

   Нарушения → отчёт → правка промпта и переразметка проблемных.
3. **Ручная вычитка всех 100 eval.** Если разметка eval кривая — метрики мусор и день насмарку.
   Train проверяется выборочно.

## 6. Baseline

Ollama на локальном железе отпадает — не хватает ресурсов под 14B.
Baseline снимаем на арендованной машине immers.cloud.

### Дорожка A — основная (рекомендуется)

**Всё в 4-bit NF4, и baseline, и после тюна.** Обе точки замера в одном квантовании →
сравнение честное, и это же реальный деплой-таргет.

- ВМ: **A10 24 ГБ, 36,6 ₽/ч** (минимальная, что тянет 14B в 4-bit инференсе)
- `transformers` + `bitsandbytes`, загрузка `Qwen/Qwen3-14B` в NF4
- 10 промптов → JSON с ответами → скачать → удалить ВМ
- Время ~30–40 мин (основное — скачивание весов), **~25 ₽**
- Если найдётся готовый 4-bit чекпоинт — берём его вместо bf16, меньше качать. Проверить на месте.

Запуск: основной путь — `baseline.py` по OpenAI-совместимому API к vLLM на ВМ
(`--quantization bitsandbytes`). Запасной — прямой `transformers`-скрипт на ВМ,
если vLLM закапризничает с квантованием. Выбираем на месте.

### Дорожка B — опция

Всё в bf16 на **A100 80 ГБ (223 ₽/ч)**, LoRA bf16 вместо QLoRA. Чище теоретически,
без квантования вообще. Итого baseline (0,5 ч) + тюн (1,5 ч) ≈ **450 ₽** против ~130 ₽.
Смысла мало: 14B в bf16 в прод никто не повезёт.

### Выбор 10 примеров

**Не случайных.** 5 случайных + 5 целевых на ловушки: бренд-vs-оттенок в кавычках,
набор, нестандартная единица, обрезанное название, отсутствующий бренд.
Случайная десятка на таком распределении даст неинформативную картину.
Пометки в файле — что есть что.

**Тот же system-промпт**, что пойдёт в датасет. Иначе сравнение «до/после» нечестное.

## 7. Критерии оценки

| метрика | что считаем | цель после тюна |
|---|---|---|
| JSON-валидность | % ответов, парсящихся как JSON, без ` ```json `-обёрток и болтовни | 100% |
| Schema compliance | все 9 ключей, типы верны | ≥98% |
| Vocab compliance | `category`/`form` ∈ словарь | ≥98% |
| Per-field exact match | по каждому полю отдельно, `null == null` = совпадение | **+15 п.п.** к baseline |
| Unit normalization | на подмножестве с «грязными» единицами (л, кг, гр, запятая, `N шт по M`) | ≥90% |
| Hallucination rate | `brand`/`line`/`shade` заполнены значением, которого нет во входе | ≤2% |
| Output length | средняя длина ответа в токенах (лекционная «экономия токенов») | **−40%** к baseline |

Абсолютные пороги калибруются по факту baseline — в день 41, сразу после замера.
