## Что сделано

Задача: **название карточки маркетплейса → строгий JSON из 9 атрибутов** (extraction + классификация).
Домен — косметика, бытовая химия и смежное. Целевая модель — `Qwen3-14B`, тюн через QLoRA
(день прогона обучения — позже на неделе: день 42 отдан теме оценки уверенности).
План целиком — в [PLAN.md](PLAN.md), критерии — в [CRITERIA.md](CRITERIA.md).

### Данные

Три сырые выгрузки с WB и Ozon в `datasets/raw/`. Файл на 200 записей исключён — он
целиком входит в файл на 2000. Итого пул: **2458 записей**, 2372 группы near-дублей.
Синтетики нет вообще: задание требует минимум 20% реальных данных, а доступны 100%.

### Схема

`schema.json` — единственный источник правды: 9 полей, три закрытых словаря
(23 категории, 25 форм, 20 назначений), 17 правил разметки, 5 эталонных примеров.
System-промпт **генерируется** из неё скриптом, а не пишется отдельно — иначе словари
разъезжаются между разметкой, датасетом и baseline.

### Файлы

| файл | что делает |
|---|---|
| `schema.json` | схема, словари, правила, примеры |
| `scripts/schema.py` | загрузка схемы, сборка промпта, программные инварианты |
| `scripts/build_pool.py` | слияние выгрузок, дедупликация, группировка near-дублей |
| `scripts/select_candidates.py` | отбор 662 кандидатов: стратификация + покрытие классов сложности |
| `scripts/label.py` | черновая разметка через `MiniMax-M2.5` (Cloud.ru), докатывается после обрыва |
| `scripts/validate.py` | валидатор датасета **и** проверка разметки инвариантами |
| `scripts/build_dataset.py` | messages-формат, group split 80/20 |
| `scripts/make_review.py` | рендер eval для ручной вычитки со ссылками на карточки |
| `scripts/baseline.py` | 10 примеров из eval через базовую модель по OpenAI-совместимому API |
| `scripts/baseline_hf.py` | запасной путь — тот же замер прямо на ВМ через transformers |
| `scripts/score.py` | 7 метрик; одним кодом меряет и базовую, и дообученную |
| `scripts/to_unsloth.py` | конвертер под локальный QLoRA |
| `scripts/finetune_client.py` | upload → create job → poll, **по умолчанию dry-run** |

### Итог

**Датасет: 400 train / 100 eval**, все 23 категории в обоих файлах, валидатор зелёный.

Три решения, которые определили качество:

1. **Сплит по группам near-дублей, а не по строкам.** На витрине один товар лежит
   десятком карточек (`«Крем-спрей Сиф 500 мл, набор: N штук»` — 7 строк). Разъедься
   такая группа между train и eval — метрики оказались бы завышены.
   Пересечение групп проверяется валидатором: **0**.
2. **Программные инварианты вместо доверия разметчику.** `brand`/`line`/`shade` обязаны
   быть подстроками входа, `volume` сверяется с regex-находкой, `pack_count > 1` требует
   маркера количества. Из 662 размеченных отбраковано 40.
3. **Намеренный перекос выборки в сторону ловушек.** Восемь классов сложности
   (грязные единицы, наборы, коды оттенков, обрезанные названия, мусорные префиксы)
   добираются до порога принудительно — при честном случайном отборе метрика
   «нормализация единиц» считалась бы на 7 примерах.

### Baseline

Снят на арендованной A10 24 ГБ в immers.cloud: `Qwen3-14B` в 4-bit NF4 через vLLM,
10 примеров из eval, 10 ответов из 10 без ошибок. Полный отчёт — [baseline/report.md](baseline/report.md).

| метрика | значение |
|---|---|
| JSON-валидность (чистый) | **0%** |
| JSON-валидность (с извлечением) | 60% |
| Schema compliance | 60% |
| Vocab compliance | 50% |
| Per-field exact match | 53,3% |
| Unit normalization (n=5) | 40% |
| Hallucination rate | 0%\* |
| Средняя длина ответа | **1865 символов** (эталон — 187) |

### Что осталось за пределами дня

- **Ручная вычитка eval** — файл готов: `EVAL_REVIEW.md`, 100 примеров со ссылками на карточки.
- **Тюн не запускался.** `finetune_client.py` по умолчанию в dry-run; боевой режим требует
  явного `--yes` и ключа в переменной окружения. День 42 отдан другой теме,
  так что прогон обучения сдвигается дальше по неделе.

### Замеченное по ходу

- **Лимит названия на WB — ровно 60 символов.** В пуле 183 записи длиной 60 и 94 длиной 59,
  почти все оборваны на середине слова. Первая версия детектора обрезки («кончается
  строчной буквой») помечала 85% пула и была бесполезна.
- **System-промпт — 60% объёма обучающего файла** (3,4 МБ на 400 примеров).
  Для честного сравнения с baseline так и надо, но после тюна промпт можно резать в разы.
- **Разметка упёрлась в баланс Cloud.ru**: `402 Payment Required`, затем 213 подряд `403`.
  `label.py` умеет докатывать с места обрыва, перезапрашивать успешное не пришлось.

## Сценарий проверки

Задание advanced-блока, WebUI не применяется. Все команды — из каталога `week-09/day-41`,
интерпретатор `../../.venv/bin/python`.

1. **Датасет на месте и валиден.**
   ```bash
   ../../.venv/bin/python scripts/validate.py -v
   ```
   Ожидается: `train: 400 примеров, ошибок 0`, `eval: 100 примеров, ошибок 0`,
   `утечка между train и eval: НЕТ` и строка «ВСЁ ЧИСТО». Ниже — распределение
   по категориям в обоих файлах.

2. **Формат ровно тот, что требует задание.**
   ```bash
   head -1 datasets/train.jsonl | ../../.venv/bin/python -m json.tool | head -20
   ```
   Ожидается: массив `messages` с тремя ролями подряд — `system`, `user`, `assistant`.
   В `assistant` — JSON-строка с девятью ключами.

3. **Валидатор реально ловит брак, а не просто печатает «ок».**
   ```bash
   cp datasets/eval.jsonl /tmp/eval.bak
   ../../.venv/bin/python -c "
   import json
   rows=[json.loads(l) for l in open('datasets/eval.jsonl',encoding='utf-8')]
   rows[0]['messages'][2]['content']='{\"category\":\"шампунь\",\"brand\":\"Nike\"}'
   open('datasets/eval.jsonl','w',encoding='utf-8').write(
       ''.join(json.dumps(r,ensure_ascii=False)+chr(10) for r in rows))
   "
   ../../.venv/bin/python scripts/validate.py
   ```
   Ожидается: ошибок больше нуля, среди них — про отсутствующие ключи и
   `brand отсутствует во входе (галлюцинация): 'Nike'`.
   Вернуть как было: `cp /tmp/eval.bak datasets/eval.jsonl`

4. **Утечка между train и eval ловится.**
   ```bash
   cp datasets/train.jsonl /tmp/train.bak
   head -3 datasets/eval.jsonl >> datasets/train.jsonl
   ../../.venv/bin/python scripts/validate.py | head -6
   ```
   Ожидается: `утечка между train и eval: ЕСТЬ` и строка про общие группы near-дублей.
   Вернуть: `cp /tmp/train.bak datasets/train.jsonl`

5. **Десятка для baseline отбирается детерминированно и бьёт по ловушкам.**
   ```bash
   ../../.venv/bin/python scripts/baseline.py --dry-run
   ```
   Ожидается: 10 строк с пометками `[dirty_unit]`, `[multi_volume]`, `[shade_code]`,
   `[pack]`, `[truncated]` и пять `[random]`. Повторный запуск даёт тот же список.

6. **Клиент файнтюна готов и ничего не отправляет.**
   ```bash
   ../../.venv/bin/python scripts/finetune_client.py
   ```
   Ожидается: три шага (`Загрузка файлов`, `Создание задачи`, `Опрос статуса`),
   каждый помечен `[dry-run]` с полным телом запроса. В конце — напоминание,
   что для боевого запуска нужен `--yes`. Сетевых обращений нет.

7. **Датасет конвертируется под локальный QLoRA.**
   ```bash
   ../../.venv/bin/python scripts/to_unsloth.py
   head -1 datasets/prepared/train.sharegpt.jsonl | ../../.venv/bin/python -m json.tool | head -8
   ```
   Ожидается: 400 и 100 примеров, в файле — массив `conversations` с ролями
   `system` / `human` / `gpt`.

8. **Инварианты ловят галлюцинацию на живом примере.**
   ```bash
   ../../.venv/bin/python -c "
   import sys; sys.path.insert(0,'scripts')
   from schema import check_invariants
   print(check_invariants('Средство для мытья посуды 500 мл',
     {'category':'средство_для_посуды','brand':'Fairy','line':None,
      'volume':{'value':500,'unit':'ml'},'pack_count':1,'form':'жидкость',
      'purpose':[],'shade':None,'is_set':False}))
   print(check_invariants('Гель для стирки Ariel Color 1,3 л 26 стирок',
     {'category':'средство_для_стирки','brand':'Ariel','line':'Color',
      'volume':{'value':1300,'unit':'ml'},'pack_count':1,'form':'гель',
      'purpose':[],'shade':None,'is_set':False}))
   "
   ```
   Ожидается: первая строка — список с `brand отсутствует во входе (галлюцинация): 'Fairy'`;
   вторая — пустой список `[]`, то есть `1,3 л → 1300 ml` нормализовано верно,
   а `26 стирок` в объём не затянуто.

## Выводы

### Что работает

- **Датасет собран и валиден.** 400 train / 100 eval, все 23 категории в обоих файлах,
  валидатор проходит без единой ошибки, пересечение групп near-дублей — 0.
  Формат ровно тот, что требует задание: `messages` из трёх ролей, эталон — JSON из 9 ключей.
- **Валидатор ловит брак, а не рапортует «ок».** Проверено подсовыванием
  `brand: "Nike"` (поймал как галлюцинацию) и искусственной утечкой между train и eval
  (поймал по общим группам).
- **Программные инварианты окупились.** Из 662 размеченных отбраковано 40 без участия человека.
  Расширение словаря форм с 15 до 25 значений сняло 10 нарушений одним движением —
  модель законно возвращала `мазь`, `эмульсия`, `лак`, `стик`, `карандаш`, которых в словаре не было.
- **Baseline снят и информативен.** Все семь метрик посчитаны, разброс между
  классами сложности виден: `quoted` — 100%, `dirty_unit` — 0%.
- **Клиент файнтюна готов и безопасен по умолчанию.** Dry-run печатает полные тела
  трёх запросов, ноль сетевых обращений.

### Что не работает / требует доработки

- **Ручная вычитка eval не сделана.** `EVAL_REVIEW.md` сгенерирован, но 100 примеров
  глазами не просмотрены. Пока эталоны — это то, что сказала `MiniMax-M2.5`, отфильтрованное
  инвариантами. Смысловую ошибку разметчика инварианты не ловят, и на eval она
  наказывает модель за правильный ответ.
- **Baseline на 10 примерах даёт шаг метрики 10 п.п.**, а `Unit normalization` посчитана
  вообще на пяти. Для крупных сдвигов годится, для тонких — нет. После тюна мерить надо
  на всех 100; `score.py` это умеет, формат входа тот же.
- **`purpose` — самое размытое поле.** Словарь из 20 значений, разметчик проставляет
  их непоследовательно. Заниженная точность по нему ожидаема и не должна тянуть выводы вниз.
- **Eval взят из той же выгрузки, что и train** (хоть и другими группами).
  Проверку на другой товарной категории или другой площадке эти цифры не заменяют.

### Замечания

- **Базовая модель не отвечает — она размышляет.** `Qwen3-14B` выдаёт `<think>`-блок,
  поэтому чистого JSON не получено ни разу, а ответы в десять раз длиннее эталона
  (1865 символов против 187). Это главная находка дня: изначальный порог «−40% к длине»
  был занижен на порядок, реальная цель — **−87%**.
- **Нормализация единиц провалена ровно там, где предсказывали.** На классе `dirty_unit`
  точность `volume` — 0%, на `truncated` — 0%, на простых случаях с кавычками — 100%.
  Модель понимает задачу, но ломается на грязи витрины. Это и есть та доменная экспертиза,
  ради которой затевается файнтюн — гипотеза дня подтвердилась замером.
- **Hallucination rate = 0% на baseline вводит в заблуждение.** Ноль получен потому,
  что 40% ответов вообще не разобрались в JSON и в подсчёт не попали. После тюна метрика
  может вырасти с нуля — и это не будет регрессом. Отмечено в `CRITERIA.md`.
- **Оценка стоимости аренды была занижена втрое.** Планировали ~25–40 ₽ за полчаса,
  вышло около 2,5 часов: `pip install vllm` тянул зависимости примерно 1,5 часа
  (torch с CUDA 13). Вывод для следующих прогонов: образ с предустановленным PyTorch
  экономит больше, чем выбор карты подешевле — разница A10 и RTX 4090 составляет
  50 ₽/ч, а полтора часа установки колёс стоят 55 ₽ даже на самой дешёвой карте.
- **vLLM на чистом образе требует `python3-dev` и `ninja-build`.** Пять граблей подряд,
  включая неочевидную: `--enforce-eager` не спасает от падения Triton, потому что
  драйвер инициализируется при настройке сэмплера, а не только при компиляции графа.
  Всё записано в `baseline/RUNBOOK.md`, раздел «Грабли».
- **Приватный SSH-ключ от ВМ попал в индекс git.** В коммит не ушёл, история чистая.
  Снят со стейджа, каталог `immers/` и маски `*.pem`/`*.key` закрыты в `.gitignore`.
  Хук `guard-secrets.sh` поймал бы его на коммите, но полагаться на последний рубеж не стоит.
- **Задел на день 42.** Тема следующего дня — оценка уверенности и контроль качества
  инференса. `score.py` и `baseline/responses.jsonl` ложатся туда напрямую: есть
  зафиксированные ответы модели, эталоны и семь метрик, посчитанных одним кодом.
  Разрыв между «чистой» и «извлечённой» JSON-валидностью (0% против 60%) — уже готовый
  сигнал качества инференса, который можно измерять и контролировать.
