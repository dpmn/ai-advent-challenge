# Runbook: прогон контроля качества на арендованной ВМ

Что делаем: снимаем на **базовой** `Qwen3-14B` (4-bit NF4) все данные, из которых
потом офлайн собирается каскад — жадные ответы с logprob-ами, по два сэмпла на
ответ и самопроверку для спорных случаев.

Прогон один. Три режима (A/B/C) и любой порог уверенности считаются потом
локально, из одного и того же `runs.jsonl`. Второй раз арендовать GPU, чтобы
подвинуть порог, не нужно — ради этого проходы 2 и 3 снимаются для всех
подходящих примеров, а не только для тех, кого отсеял порог.

## 1. Поднять ВМ

Фактический прогон 29.07.2026 шёл на **RTX 4090 24 ГБ**, 86,74 ₽/ч
(8 vCPU, 32 ГБ ОЗУ, 160 ГБ диск). A10 из дня 41 планировалась, но свободных
не нашлось — на цену прогона это почти не влияет, потому что платим за минуты.
Образ голый, без CUDA-стека: `torch` не предустановлен.

vLLM не нужен: прогон идёт через `transformers` напрямую, как запасной путь дня 41.
Половина граблей дня 41 (`ninja-build`, `pkill`, `--enforce-eager`) относилась
именно к vLLM и здесь неприменима. Актуальными остаются `python3-dev` и `setsid` —
разобраны в [day-41/baseline/RUNBOOK.md](../day-41/baseline/RUNBOOK.md).

**Разворачивать одним детач-скриптом, а не руками в сессии.** День 41 показал,
что `nohup ... &` внутри `ssh host 'команда'` умирает вместе с сессией.

```bash
scp -i immers/<ключ>.pem -o IdentitiesOnly=yes bootstrap.sh ubuntu@<IP>:~/
ssh -i immers/<ключ>.pem -o IdentitiesOnly=yes ubuntu@<IP> \
  'chmod +x ~/bootstrap.sh && setsid nohup ~/bootstrap.sh </dev/null >~/bootstrap.log 2>&1 &'
```

Содержимое `bootstrap.sh` — в [scripts/bootstrap.sh](scripts/bootstrap.sh).
Следить: `grep -E "^=== " ~/bootstrap.log`.

### Установка занимает 2,5 минуты, а не полтора часа

Главный вывод дня 41 — «`pip install` съел 1,5 часа, образ с предустановленным
PyTorch экономит больше, чем выбор карты подешевле» — оказался **неверно
адресован**. Дело было не в образе.

| этап | время |
|---|---|
| apt (`python3-dev`, `build-essential`) | 30 с |
| установка `uv` | 1 с |
| `uv pip install torch transformers accelerate bitsandbytes` | 41 с |
| скачивание весов `Qwen3-14B`, 28 ГБ | 76 с |
| **итого от чистого образа до готовности** | **2 мин 30 с** |

Полтора часа дня 41 давали две вещи, обе устранимые:

- **`pip` резолвит и качает последовательно.** `uv` делает это параллельно.
  На дереве зависимостей масштаба torch разница — десятки минут.
- **Тянулся `vllm`**, а он подтягивает CUDA-стек целиком (flashinfer, xformers,
  Triton со сборкой). `transformers` обходится тем же torch без обвязки.

То есть предустановленный PyTorch экономит около минуты, а не полутора часов.
Вывод дня 41 в этой части поправлен.

## 3. Дымовой прогон на трёх примерах

Сначала три примера, а не пятьдесят: батчевая генерация с `output_scores`
на 4-bit — единственное место, которого не было в дне 41, и ломается оно
на загрузке модели, а не на пятидесятом примере.

```bash
cd ~/day-42 && .venv/bin/python run_gates.py \
  --model ~/qwen3-14b --limit 3 --batch-size 3 --out smoke.jsonl
```

Что должно быть в выводе: три прохода отработали, `smoke.jsonl` непустой,
в `base.tokens` у записей есть числа. Если `compute_transition_scores` падает —
прогон всё равно возможен без ступени 2 (см. «Если logprob-ы не снялись»).

## 4. Основной прогон

```bash
cd ~/day-42 && .venv/bin/python run_gates.py \
  --model ~/qwen3-14b --batch-size 8 --out runs.jsonl
```

Ориентир: 50 базовых вызовов + до 100 сэмплов + самопроверки. При батче 8
это заметно быстрее, чем 48 с/ответ у дня 41 (там batch=1). В конце скрипт
печатает GPU-время и стоимость и кладёт их в `runs.meta.json`.

Забрать и **сразу погасить ВМ**:

```bash
scp -i immers/<ключ>.pem -o IdentitiesOnly=yes \
  ubuntu@<IP>:~/day-42/runs.jsonl ubuntu@<IP>:~/day-42/runs.meta.json results/
```

## Если logprob-ы не снялись

`compute_transition_scores` на 4-bit не проверялся до этого прогона. Если он
падает, ступень 2 остаётся без данных: `score_confidence` вернёт пустую оценку,
каскад отправит все ответы в избыточность, и цена вырастет. Прогон при этом
не ломается — но в отчёте это надо назвать прямо, а не выдавать за результат.

Запасной вариант — заменить scoring на self-reported confidence отдельным
вызовом. Это +1 вызов на каждый ответ, то есть дороже ровно того, ради чего
scoring и брался бесплатным.
