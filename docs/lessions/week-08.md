# Неделя 8. Код-ассистент

## Архитектура код-ассистента

Современная система ИИ-помощника состоит из нескольких уровней:

- **Main Agent (Главный агент):** Ваша точка входа (например, Claude Code, Cursor), которая интерпретирует команды и выступает в роли «мини-ОС», управляя инструментами (Bash, HTTP-клиенты) и распределяя задачи.
- **Субагенты:** Специализированные подпроцессы с собственным контекстом и системным промптом, которые решают локальные задачи изолированно.
- **Скиллы (Навыки):** Конкретные способности, которые агент может быстро подхватить и выполнить (например, суммаризация PR).
- **Команды:** Интерфейс управления в виде шорткатов (горячих клавиш), избавляющий от необходимости каждый раз писать длинные промпты.

## Execution Loop (Цикл исполнения)

Главный результат настройки — создание уникального **Execution Loop**, который отражает ваш стиль работы и майндсет.

- **Процесс:** Задача попадает к главному агенту, который регистрирует её и запускает субагентов для изучения, планирования и исполнения.
- **Роль главного агента:** Он не должен выполнять работу сам, его задача — **планирование, маршрутизация и контроль**, чтобы избежать переполнения контекстного окна (которое составляет около 160–180 тыс. токенов) и потери качества ответов.


## Тюнинг и правила (Rules)

Для стабильной работы системы необходимо настроить иерархию правил:

1. **Глобальные правила:** Регламентируют ваш общий стиль работы и привычки.
2. **Проектные правила:** Нужны для **переопределения (наследования)** глобальных правил под конкретный стек или дизайн-систему проекта.
3. **Профили:** Набор инструкций, который описывает ваш «отпечаток» как разработчика (привычки, предпочтения в общении и профессиональный уровень).
4. **Инварианты:** Жесткие ограничения (например, «всегда писать только на Python»), которые модель не должна нарушать.
5. **Состояния (States):** Четко прописанные стадии флоу (исследование, план, исполнение, валидация), предотвращающие хаос в изменениях.


## Работа с субагентами

Субагенты могут работать в разных режимах делегирования:

- **Параллельно:** Экономит массу времени (до 10 раз), запуская несколько **независимых** задач одновременно.
- **Последовательно (цепочкой):** Когда результат работы одного агента **критически важен** для следующего (например, после кодинга идет тестировщик).
- **По условию (роутер):** Например, возврат задачи кодеру, если ревьюер нашел ошибки.

Для эффективной работы с субагентами в рамках создания **Execution Loop** код-ассистента выделяют следующие **лучшие практики**:

- Для минимизации галлюцинаций и экономии токенов рекомендуется прописывать для субагентов **четкие входные и выходные контракты** (форматы данных и артефакты).
- Важно учитывать технические ограничения — например, Claude Code позволяет запускать **не более пяти субагентов одновременно**. Большое количество одновременно работающих агентов сильно нагружает систему и приводит к огромному расходу токенов.
- Желательно запускать субагентов в действительно независимых средах (Worktree), чтобы их работа с файлами не пересекалась.
- Субагент должен уметь самостоятельно проверять выполнение своей задачи и «отстукиваться» мейн-агенту о завершении работы. Можно также настроить уведомления о завершении работы субагентов в фоновом режиме (например, через Telegram или фразы-хуки).



## Профит от настройки

Правильно настроенный Execution Loop позволяет:

- **Параллелить работу:** Запускать множество задач одновременно.
- **Получать Production Ready код:** Результат будет выглядеть так, как будто его писали вы (Senior-уровень).
- **Экономить время:** Час, потраченный на настройку правил и инвариантов, экономит десятки часов на дебаге и исправлениях в будущем.
