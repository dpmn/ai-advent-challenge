# Неделя 7 — День 31. Ассистент разработчика

## Задание

**Используйте RAG для подключения к документации вашего проекта:**
- README
- project/docs
- схемы данных или API-описания

**Через MCP подключите ассистента к проекту:**
- минимум — получение текущей git-ветки
- по желанию — список файлов или diff

**Реализуйте команду:**
- `/help` — ассистент отвечает на вопросы о проекте
- использует документацию и контекст проекта

**Минимальный результат:**
- README + папка docs в RAG
- MCP — хотя бы git branch
- `/help` отвечает на вопросы о структуре проекта

**Результат:**
- Ассистент разработчика, понимающий проект

## Реализация

Вместо расширения Jarvis сделан отдельный портабельный CLI-ассистент **`docent`**
(ставится как pip/uv-пакет, работает в любом репозитории). Новый каталог в корне
`docent/`, без зависимостей от Jarvis.

Что и где:

- `docent/pyproject.toml` — пакет, entry point `docent = docent.cli:main`, deps
  `mcp`, `numpy`, `httpx`.
- `docent/docent/cli.py` — команды `init` / `ask` / `help` / `auth`.
- `docent/docent/config.py` — пути `.docent/`, чтение ключа из `CLOUDRU_SECRET_KEY`,
  реестр моделей (`MODELS`, дефолт `Qwen/Qwen3-Coder-Next`) — задел под
  opencode-style выбор модели.
- `docent/docent/llm.py` — httpx-клиент Cloud.ru (chat + embeddings), без openai SDK.
- `docent/docent/rag/` — лёгкий RAG: `chunker.py` (markdown по заголовкам + окно),
  `store.py` (brute-force косинус на numpy), `index.py` (build/query). Индекс в
  `.docent/` (`index.npy` + `chunks.json`), без FAISS/reranker.
- `docent/docent/mcp/` — MCP-слой под несколько серверов: `registry.py` (реестр),
  `manager.py` (поднимает включённые серверы как stdio-подпроцессы, агрегирует
  тулзы), `servers/git.py` (`git_current_branch`, `git_head`, `git_list_files`).
  Транспорт stdio — ни портов, ни ручного запуска сервера.
- `.gitignore` — добавлен `.docent/`.
- Удалён прототип `mcp_servers/project_tools_mcp/` (git-логика перенесена в
  `docent/docent/mcp/servers/git.py`, транспорт сменён на stdio).

Проверка идёт в терминале (это CLI, не WebUI).

### Сценарий проверки

Предусловие: в окружении задан `CLOUDRU_SECRET_KEY` (ключ Cloud.ru), пакет
установлен (`uv pip install -e ./docent` или `pip install -e ./docent`).

1. В корне репозитория выполни:
   ```
   docent help
   ```
   Ожидаемо: список команд `init` / `ask` / `help` / `auth`.

2. Построй индекс по документации проекта:
   ```
   docent init
   ```
   Ожидаемо: строка `Готово: файлов N, чанков M. Индекс: .docent/` (N ≥ 1, M > 0);
   появился каталог `.docent/` с `config.json`, `index.npy`, `chunks.json`.

3. Спроси про структуру проекта:
   ```
   docent ask "Из каких основных каталогов состоит проект и за что они отвечают?"
   ```
   Ожидаемо: связный ответ, упоминающий `agents/`, `ragger/`, `webui/`,
   `mcp_servers/` (взято из документации через RAG); в конце строка `Источники: …`
   с реальными файлами (`README.md` / `CLAUDE.md` / `docs/...`).

4. Проверь git-контекст через MCP:
   ```
   docent ask "На какой git-ветке я сейчас нахожусь?"
   ```
   Ожидаемо: в ответе фигурирует текущая ветка (`day-31`) — значение получено
   инструментом `git_current_branch` MCP-сервера, а не выдумано.

5. Проверь честность на отсутствующем в доках вопросе:
   ```
   docent ask "Какой пароль от production-базы?"
   ```
   Ожидаемо: ассистент честно отвечает, что таких данных в документации нет
   (не выдумывает).

## Выводы

### Что работает
- `docent help` / `docent init` / `docent ask` — все команды отрабатывают.
- Индексация: `docent init` собрал 11 файлов / 138 чанков в `.docent/`.
- RAG по документации: на вопрос о структуре проекта дан корректный ответ с
  реальными источниками (`docs/progress.md`, `docs/database-schema.md`, лекции).
- git-контекст через MCP: на «на какой ветке я сейчас» ассистент верно ответил
  `day-31` — значение пришло от инструмента `git_current_branch`, не выдумано.
- Анти-галлюцинации: на вопрос про пароль production-базы ассистент честно
  сказал, что таких данных в документации нет.

### Что не работает / требует доработки
- **Нет ответа на «что изменилось в ветке».** На «какие файлы изменены / проверь
  через git diff» ассистент лишь объясняет git-команды, но не отвечает. Причина:
  MCP-сервер отдаёт только `git_current_branch` + `git_head`, тула `git_diff` /
  `git_status` нет, а git-контекст инжектится детерминированно (без agentic
  tool-calling) — модель не может сама вызвать нужный инструмент. Доработка:
  добавить `git_diff`/`git_status` в `mcp/servers/git.py` и/или цикл вызова
  инструментов моделью.
- **Фактическая ошибка про неделю.** Модель заявила, что день 31 относится к
  «неделе 6». Корень: `docs/progress.md` заканчивается на дне 30, записи про
  week-07/day-31 нет — при бедном git-контексте (только ветка+коммит) модель
  домыслила. После обновления `progress.md` (docs-sync) ошибка должна уйти.
- **«Источники» вводят в заблуждение.** Строка перечисляет все RAG-попадания
  независимо от того, использованы ли они в ответе. На вопрос про git-ветку в
  источники попали `progress.md` / `database-schema.md`, хотя ответ дал MCP-тул,
  а не эти доки. Атрибуция декоративная, а не причинная.

### Замечания
- FastMCP пишет `Processing request of type ...` в stderr — шум в терминале при
  каждом `ask`. Стоит приглушить логирование stdio-сервера.
- Минимальный git-контекст (ветка + последний коммит) — сознательное решение под
  минимум задания. Для вопросов «что поменялось» его недостаточно (см. выше).
