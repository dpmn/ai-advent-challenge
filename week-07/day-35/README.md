## Что сделано

**Задача:** ответ на бытовой вопрос «что бы приготовить из того, что есть в холодильнике?» —
MVP пет-проекта **fridge-chef** (отдельный репозиторий: [github.com/dpmn/fridge-chef, ветка `mvp`](https://github.com/dpmn/fridge-chef/tree/mvp)).

**Пайплайн:** продукты → варианты блюд (retrieval по корпусу, без LLM) → полный рецепт (LLM).
Формат — пошаговый wizard-UI, не чат: каждый LLM-вызов самодостаточен, проблемы смешивания
контекста нет по построению, API stateless.

**Роль AI:**
- LLM (`deepseek-ai/DeepSeek-V4-Flash`, Cloud.ru) разворачивает найденный рецепт в полный,
  адаптируя под имеющиеся продукты (`combine`), и импровизирует с явной пометкой,
  когда retrieval ничего не нашёл (`creative`);
- весь код написан AI (вайбкодинг по правилам репозитория fridge-chef: ворота фаз,
  go-style skill, ревью субагентом go-reviewer).

**Что внутри (все файлы — в репозитории fridge-chef):**
- `ingestion/build_corpus.py` — сборка корпуса из датасета povarenok.ru (147k рецептов,
  срез 5000): нормализация ингредиентов, `corpus/v001/` (recipes.jsonl + manifest + canon.json);
- Go-сервис (stdlib-only): `internal/corpus` (in-memory корпус + канонизация пользовательского
  ввода), `internal/match` (coverage-скоринг), `internal/llm` (OpenAI-совместимый клиент,
  ретрай/таймауты), `internal/generate` (промпт-стратегии strict/combine/creative),
  `internal/api` (HTTP), `web/` (wizard-UI, вшит в бинарник);
- тесты table-driven во всех пакетах, `go vet`/`gofmt` чисто.

**Отклонение от роадмапа fridge-chef** (осознанное, зафиксировано в его roadmap.md):
вертикальный срез без векторной БД и эмбеддингов; F0/F3/F6 закрыты, F2/F4 частично, F1/F5/F7 впереди.

**Деплой:** finland-vds (1 vCPU / 2 GB), docker compose (`/opt/fridge-chef`, контейнер на
`127.0.0.1:8081`), nginx-прокси с таймаутами под LLM, TLS Let's Encrypt с автопродлением,
редирект HTTP→HTTPS. Продакшн: **https://fridge-chef.ru**. Попутно mtproto-proxy перенесён
с 443 на 2443 — порт был нужен под HTTPS.

### Сценарий проверки

Продакшн: https://fridge-chef.ru. Локально — `go run ./cmd/fridge-chef` в каталоге
fridge-chef (нужен `.env`, см. README репо) и тот же сценарий на http://localhost:8080.

1. Открой https://fridge-chef.ru — страница «fridge-chef: что бы приготовить?»
   (замок TLS в адресной строке на месте).
2. Введи продукты: `творог, яйца, мука, сметана` и нажми «Что приготовить?».
3. Ожидаемый результат: список карточек, первой — «Воздушные сырники» со 100% покрытия
   и пометкой «всё есть!». В карточках видно процент покрытия и чего не хватает.
4. Нажми «Состав» у первой карточки — мгновенно (без LLM) выводится состав с количествами
   и ссылкой на источник povarenok.ru.
5. Вернись «← к вариантам», нажми «Готовим! 🍳» — за ~минуту LLM выдаст полный рецепт:
   шаги приготовления, адаптация под введённые продукты, ссылка на источник.
6. Проверь, что в рецепте нет пометок «нужно докупить» для соли/сахара/воды (базовые
   продукты считаются имеющимися).
7. Вернись к вводу продуктов, введи `дуриан` и нажми «Что приготовить?».
8. Ожидаемый результат: честное «Подходящего рецепта не нашёл» и кнопка
   «✨ Придумай блюдо из моих продуктов».
9. Нажми её — LLM сгенерирует блюдо, ответ начинается с пометки
   «Импровизация: рецепт придуман, а не взят из базы».
10. Введи разговорные названия: `картошка, грибочки, лук` — сервис нормализует их
    (в списке продуктов над карточками — «картофель, грибы, лук») и предложит блюда
    из картофеля и грибов.

## Выводы

### Что работает

- Основной сценарий пройден полностью на проде (https://fridge-chef.ru, видео записано):
  подбор по продуктам, карточки с покрытием, strict-состав без LLM, combine-рецепт с адаптацией,
  честное «не нашёл» + creative с пометкой импровизации, нормализация разговорных названий.
- Деплой-цепочка целиком: docker compose на finland-vds, nginx-прокси, TLS Let's Encrypt,
  редирект HTTP→HTTPS. Все запросы сессии проверки в логах — 200, ошибок приложения нет.
- Устойчивость к бредовому вводу: на «дрова, рука железного человека, лапка лягушки» retrieval
  честно ничего не нашёл, creative провёл съедобные аналогии (дрова→грибы, лапка→курица) —
  приемлемо для режима, который явно помечен как импровизация.

### Что не работает / требует доработки

- «Load failed» при творческой генерации на iPhone: ошибка не серверная — Safari обрывает
  fetch по своему таймауту ~60 с, а генерация заняла ~минуту (сервер довёл её до конца
  и вернул 200 уже «в никуда»). Доработка: стриминг ответа (SSE) и/или ограничение
  `max_tokens` — заодно улучшит UX ожидания.
- Prompt-injection через поле продуктов: запрос «напиши функцию на python…» доехал до LLM
  как список «продуктов». Нужна валидация ввода до вызова LLM (фильтр не-продуктов
  или инструкция модели отказываться от не-кулинарных запросов).

### Замечания

- Датасет povarenok не содержит шагов приготовления — шаги всегда генерирует LLM; strict-режим
  из-за этого отдаёт только состав со ссылкой на источник. Для полноценного strict нужен
  источник с шагами (парсинг страниц или другой датасет).
- Время combine-генерации нестабильно: 28–65 с на одинаковых запросах (DeepSeek-V4-Flash).
  Для прода стоит замерять и, возможно, добавить фоллбек-модель побыстрее.
- Порт 443 на VDS пришлось освобождать от mtproto-proxy (перенесён на 2443) — на будущее:
  под публичные продукты лучше держать отдельный от прокси-экспериментов сервер.
