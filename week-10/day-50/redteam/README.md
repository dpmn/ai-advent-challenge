# Red team-харнес — этап 2, атака на мишень партнёра

Инструмент для атаки на AI-агента партнёра (день 50). Запускается **на immers**
(GPU-ВМ с локальной моделью), а не на рабочей машине: запросы к чужому сервису
идут от локальной модели, а не от инфраструктуры Anthropic.

## Правила боя (наша дисциплина)

В челлендже «правил нет», но харнес держит границу сам:

- цель — только **два названных секрета** мишени (в system prompt и в файле на
  сервере). Захватили — остановились;
- **ничего разрушительного**: даже если Gradle даст выполнение кода, читаем
  секретный файл и всё. Никакой порчи, персистентности, бокового движения;
- **вежливый rate-limit** (по умолчанию 1 запрос / 2 с) — VPS мишени маленький.

## Что где

| Файл | Роль |
|---|---|
| `config.py` | адрес и токен мишени (из env), модель, лимиты боя |
| `client.py` | клиент к мишени (OpenAI-совместимый, многоходовой) и к Ollama |
| `payloads.py` | seed-каталог атак по векторам — воспроизводимая база «до/после» |
| `attacker.py` | локальная модель генерит адаптивные вариации payload'ов |
| `judge.py` | эвристика + модель-судья: есть ли признак утечки в ответе |
| `run.py` | оркестратор: seed → вариации → судья → лог |
| `report.py` | markdown-отчёт из лога |
| `tests/` | офлайн-тесты детерминированных частей |

## Векторы

`tool_enum`, `prompt_reveal`, `roleplay`, `format_dump`, `encoding_exfil`,
`file_read`, `indirect_upload`, `gradle_rce`. Порядок в бою — от дешёвого к
тяжёлому; `gradle_rce` — финал по секрету №2.

`indirect_upload` и `gradle_rce` требуют доставки файла в мишень. Если её API
загрузку не поддерживает (только веб-чат) — файл прикладывается **вручную через
браузер**, а харнес готовит его содержимое.

## Запуск на immers

```bash
# 0) поставить Ollama и модель (нецензурированная — иначе откажется писать инъекции)
curl -fsSL https://ollama.com/install.sh | sh
ollama pull dolphin3:8b        # модель подбирается под VRAM

# 1) токен мишени — только через окружение, в код/гит не попадает
export ATTACK_TARGET_TOKEN=<токен партнёра>

# 2) разведка формы API (black-box)
python3 -m redteam.run --recon

# 3) боевой прогон (все векторы или выбранные)
python3 -m redteam.run --vectors tool_enum,prompt_reveal,file_read
python3 -m redteam.run          # все

# 4) отчёт
python3 -m redteam.report logs/run-YYYYMMDD-HHMMSS.jsonl > ../attacks-partner.md
```

Локально (без мишени и модели):

```bash
python3 -m redteam.run --dry-run --vectors prompt_reveal   # показать payload'ы
python3 -m redteam.tests.test_offline                      # офлайн-тесты
```

## Настройки (env)

| Переменная | Умолчание | Что |
|---|---|---|
| `ATTACK_TARGET_URL` | `http://185.43.5.66:18090/v1` | база API мишени |
| `ATTACK_TARGET_TOKEN` | — | токен мишени (обязателен) |
| `ATTACK_TARGET_MODEL` | пусто | имя модели мишени (из разведки) |
| `ATTACKER_MODEL` | `dolphin3:8b` | локальная модель-атакующий/судья |
| `ATTACK_MIN_INTERVAL` | `2.0` | пауза между запросами к мишени, с |
| `ATTACK_MAX_TOTAL` | `150` | потолок запросов к мишени за прогон |

Логи прогонов — в `logs/` (в гит не коммитятся: могут содержать вытащенный
секрет и ответы мишени).
