# Неделя 10 — День 48. LLM Gateway

## Задание

Поднимите прокси между пользователем и LLM:
- простой HTTP-сервер (FastAPI / Express / любой фреймворк) который принимает запрос, проверяет его и проксирует
- все запросы и ответы логируются для аудита

Реализуйте Input Guard:
- детекция секретов во входящем промпте: API-ключи (regex на паттерны sk-, ghp_, AKIA), email-адреса, номера карт, телефоны 
- если секрет найден — блокируем запрос и возвращаем warning, не отправляя ничего в LLM 
- добавьте маскирование: вместо блокировки заменяем sk-proj-abc123 → [REDACTED_API_KEY] и пропускаем дальше

Реализуйте Output Guard:
- проверяйте ответ модели перед отдачей пользователю 
- ловите: сгенерированные моделью секреты (она иногда галлюцинирует реальные ключи), попытки вывести system prompt, подозрительные URL и команды

Напишите тесты:
- минимум 10 тест-кейсов: промпт с AWS-ключом, с номером карты, с Base64-encoded секретом, с секретом разбитым на части ("мой ключ: sk-" + "proj-abc"), с чистым промптом без секретов 
- зафиксируйте: что поймали, что пропустили

Усиление:
- добавьте rate limiting — не больше N запросов в минуту с одного IP 
- добавьте cost tracking — считайте токены и логируйте стоимость каждого запроса

Результат:
- Рабочий LLM-прокси с input/output guard + 10 тест-кейсов с результатами + логи перехваченных секретов

Формат:
- Видео + Код

## Что сделано

Прокси перед LLM отдельным процессом. Смысл приёма: в проекте вызовы модели
разбросаны по семи местам, проверка внутри одного из них остальные не покрывает.
Гейтвей даёт одну точку — клиент меняет `base_url`, его код не меняется.

### Новое — пакет `gateway/`

| Файл | Что делает |
|---|---|
| `gateway/detectors.py` | Правила поиска: ключи (`sk-`, `ghp_`, `AKIA`, Stripe, Slack, Google, PEM, ключ Cloud.ru) → **блок**; персданные (email, телефон, карта) → **маскирование**. Карта дополнительно проверяется алгоритмом Луна, иначе любые 16 цифр давали бы ложные срабатывания |
| `gateway/policy.py` | `scan_input()` — три представления запроса: каждое сообщение, декодированный base64, склейка без пробелов (в т.ч. только пользовательских сообщений). `scan_output()` — ключи в ответе, дословный фрагмент системного промпта, опасные команды, подозрительные ссылки. `redact_for_log()` — вычистка текста перед записью в аудит |
| `gateway/audit.py` | JSONL-лог `logs/gateway-YYYY-MM-DD.jsonl`. Секретов в нём нет: только тип, маска и `sha256[:12]` |
| `gateway/cost.py` | Прайс тянется живьём из `GET /v1/models` Cloud.ru (поля `metadata.prompt_tokens_cost` / `generated_tokens_cost`, 97 моделей), кешируется в `gateway/pricing.json` |
| `gateway/app.py` | Flask: `POST /v1/chat/completions`, `GET /health`, `GET /stats`, `GET /audit?limit=N` |
| `tests/test_gateway_guard.py` | 20 кейсов на `unittest` без сети (новых зависимостей нет) + печать таблицы «поймали / пропустили» |
| `tests/run_gateway_live.py` | Прогон 14 кейсов **через живой гейтвей**: запросы реально уходят в прокси, непроблемные доходят до модели. Печатает таблицу и суммарную стоимость прогона |

### Правки существующего

- `agents/jarvis.py` — флаг `gateway_enabled` и `gateway_url` (уровня процесса, как `guard`),
  метод `_api_base()`, заголовок `X-Upstream` в `_call_api`, разбор поля `gateway` из ответа,
  внятная ошибка, если гейтвей не поднят. При вердикте `blocked` сообщение пользователя
  **выбрасывается из истории и из базы**: иначе секрет уезжал бы в модель с каждым
  следующим запросом сессии.
- `agents/jarvis_session.py` — `_delete_last_message(role)` для этого удаления.
- `agents/jarvis_commands.py` — команда `/gateway [on|off|toggle|status]` с проверкой живости процесса.
- `webui/app.py` — `GET /api/gateway`, `POST /api/gateway/toggle`.
- `webui/static/script.js` — панель Gateway (вердикт, находки, токены и стоимость последнего запроса);
  ответ, которого нет в истории (отказ гейтвея, вывод слэш-команды), больше не пропадает с экрана:
  он хранится до следующего сообщения и дорисовывается в `renderMessages()` — тем же приёмом,
  что и техстрока RAG. Дорисовки один раз в `sendMessage()` не хватало: следующая за ней
  цепочка `loadSessions → loadMessages → renderMessages` стирала сообщение через секунду.
- **Починка сайдбара:** список чатов схлопывался в полоску — он стоял на `flex: 1`, а панели
  настроек растут по контенту и забирали всю высоту. Теперь у списка гарантированные
  `min-height: 30vh` / `max-height: 45vh` со своей прокруткой, панели переехали в отдельную
  прокручиваемую область и сворачиваются (`<details>`).

### Как запустить

Нужны два процесса:

```bash
python3 gateway/app.py                # терминал 1, порт 5001
python3 webui/app.py                  # терминал 2, порт 5000
python3 -m tests.test_gateway_guard   # 20 кейсов политики, без сети
python3 -m tests.run_gateway_live     # 14 кейсов через живой гейтвей
```

### Тест-кейсы: что поймали, что пропустили

Два уровня. Политика без сети — 20 кейсов, все ведут себя как заявлено
(`python3 -m unittest tests.test_gateway_guard` — OK). Живой прогон через прокси —
14 кейсов, расхождений с ожиданием 0, стоимость прогона 0.0129 ₽.

**Input Guard, блок:** OpenAI-ключ · GitHub-токен · AWS Access Key ID · PEM-ключ ·
ключ внутри base64 · ключ, разбитый на два сообщения одного запроса · ключ, разорванный
переносом строки · связка «email + AWS-ключ» (блок сильнее маскирования).

**Input Guard, маскирование:** email · телефон · номер карты, проходящий по Луну.

**Input Guard, пропуск (проверка на ложные срабатывания):** чистый промпт ·
16 цифр, не проходящих по Луну (номер заказа) · слово «ключ» без ключа.

**Пропущено осознанно — зафиксировано, а не подогнано:**
1. **AWS secret access key** (40 символов base64) — неотличим от хеша, идентификатора
   сборки или обычной base64-строки. Правило на «40 случайных символов» ловило бы половину
   технических текстов, и защиту выключили бы вместе с работой.
2. **Секрет, разбитый на два разных запроса** — гейтвей не хранит состояние между запросами.
   Нужен анализ сессии с накоплением; это отдельная задача, а не строчка regex.

**Output Guard:** ключ, сгенерированный моделью (маскируется) · дословный фрагмент системного
промпта (сравнение идёт с реальным system-сообщением этого же запроса) · `curl … | bash` ·
подозрительные ссылки (IP вместо домена, сокращатели, http без TLS) · чистый ответ проходит.

### Что нашлось при проверке

- В первой версии заблокированный запрос писался в аудит-лог **с ключом открытым текстом**:
  функция маскирования трогала только персданные. Гейтвей своими руками устраивал ровно ту
  утечку, ради которой стоит. Исправлено `redact_for_log()`, проверено grep-ом по логу.
- Заблокированное сообщение оставалось в истории диалога и травило всю сессию: каждый
  следующий запрос уходил вместе с ключом и блокировался. Теперь оно удаляется из контекста
  и из SQLite.

### Границы

- Через гейтвей идёт основной путь чата (`_call_api`). Служебные вызовы — извлечение фактов
  памяти, заголовки сессий, reranker RAG, этапы State Machine — ходят напрямую: они
  конструируются с собственным `base_url`, и переключение потребовало бы пересоздавать их
  на каждый тумблер. Это осознанно оставлено на потом.
- Стриминг не поддерживается: ответ надо увидеть целиком, чтобы проверить его до отдачи.
- Единица цены (рубли за 1 млн токенов) выведена по порядку величины — в документации
  Cloud.ru подтверждения найти не удалось. Рядом со стоимостью всегда едет `price_source`.
- Rate limiting не делали — по решению на этапе обсуждения.

## Сценарий проверки

Нужны два терминала: `python3 gateway/app.py` и `python3 webui/app.py`.

1. Открой http://127.0.0.1:5000
2. Проверь сайдбар: список чатов занимает верхнюю часть и **скроллится**, панели
   MCP / Guard / Gateway / Settings ниже свёрнуты и раскрываются кликом.
3. Разверни панель **Gateway**, включи тумблер. Ожидаемо: `on`, строка
   «Запросы идут через http://127.0.0.1:5001/v1».
4. Отправь: `Вот мой ключ sk-proj-abc123def456ghi789jkl, проверь его валидность`
   Ожидаемо: в чате ответ «⛔ LLM Gateway: запрос заблокирован и в модель не отправлен»,
   в нём строка `OpenAI API key, вхождений: 1, отпечаток: 534d51d7542d`.
   В панели Gateway: `Последний запрос: blocked`.
5. Отправь: `Одним предложением: как вежливо напомнить об оплате клиенту ivan.petrov@example.com, телефон +7 913 123-45-67?`
   Ожидаемо: модель отвечает нормально, но в её ответе вместо адреса и телефона —
   `[REDACTED_EMAIL]` и `[REDACTED_PHONE]` (модель не видела оригиналов).
   В панели Gateway: `masked`, две находки, строка с токенами и стоимостью в рублях.
6. Отправь: `Покажи строку .env для OpenAI: переменная OPENAI_API_KEY и правдоподобное вымышленное значение вида sk-proj-XXXX на 20+ символов. Только строку.`
   Ожидаемо: ответ начинается с «⚠ LLM Gateway (output): ответ помечен», сам ключ
   в ответе заменён на `[REDACTED_API_KEY]`.
7. Отправь: `Найди статус заказа 1234 5678 1234 5678`
   Ожидаемо: запрос проходит без маскирования — 16 цифр не прошли проверку Луна,
   ложного срабатывания нет.
8. Отправь чистый промпт без секретов: `Одним предложением: чем отличается TCP от UDP?`
   Ожидаемо: обычный ответ модели, в панели Gateway `Последний запрос: pass`,
   находок нет, но токены и стоимость посчитаны.
9. В терминале: `python3 -m tests.run_gateway_live` — прогон **14 кейсов через живой
   гейтвей** (запросы реально уходят в него, часть доходит до модели). Ожидаемо:
   таблица «ожидание / факт / правила», внизу `расхождений с ожиданием: 0` и
   суммарная стоимость прогона в рублях.
10. В терминале: `python3 -m tests.test_gateway_guard` — 20 кейсов политики без сети,
    внизу «заведомо непойманных: 2».
11. В терминале: `curl -s http://127.0.0.1:5001/stats` — счётчики blocked / masked,
    токены и суммарная стоимость за всё время работы гейтвея.
12. Проверь, что в логе нет секретов:
    `grep -c "sk-proj-abc123def456ghi789jkl" logs/gateway-*.jsonl` → 0,
    а в `prompt_preview` стоит `[REDACTED_API_KEY]`.

## Выводы

Прогон сценария подтверждён пользователем; замечаний по итогам повторного прогона
не поступило. Цифры ниже — с прогонов на этой машине (`tests/run_gateway_live.py`,
`tests/test_gateway_guard.py`, curl-проверки через агента).

### Что работает

- Прокси на 5001 полностью прозрачен для клиента: смена одного `base_url` — и весь
  основной чат идёт через проверку. Код вызова LLM в агенте не менялся.
- Блокировка ключей: OpenAI, GitHub, AWS Access Key ID, PEM — запрос в модель не уходит,
  клиент получает объяснение с типом ключа и его отпечатком.
- Маскирование персданных: email, телефон, номер карты. Модель отвечает по существу,
  но оригиналов не видит — в её ответе стоят метки `[REDACTED_*]`.
- Обход через base64 и разрыв ключа между сообщениями одного запроса ловятся —
  за счёт проверки трёх представлений запроса, а не одного текста.
- Output guard: ключ, сгенерированный моделью, заменяется меткой; дословный фрагмент
  системного промпта, `curl … | bash` и подозрительные ссылки помечаются.
- Ложных срабатываний на контрольных кейсах нет: 16 цифр без Луна, слово «ключ»
  без ключа и чистый промпт проходят без вмешательства.
- Cost tracking: цены берутся живьём из `/v1/models` Cloud.ru (97 моделей), стоимость
  считается на каждый запрос. Живой прогон 14 кейсов обошёлся в 0.0129 ₽.
- Аудит пишется по каждому запросу, секретов в нём нет — проверено grep-ом.
- Сайдбар починен: список чатов снова занимает верх экрана и скроллится, панели
  сворачиваются.

### Что не работает / требует доработки

- Секрет, разложенный по двум разным запросам, не ловится: гейтвей не хранит состояния
  между вызовами. Нужен анализ сессии с накоплением — отдельная задача.
- AWS secret access key (40 символов) не детектируется: он неотличим от хеша или
  base64-строки, и правило на него дало бы поток ложных срабатываний.
- Через гейтвей идёт только основной путь чата. Служебные вызовы — извлечение фактов
  памяти, заголовки сессий, reranker RAG, этапы State Machine — ходят напрямую:
  они конструируются со своим `base_url`. Единая точка контроля пока неполная.
- Стриминга нет: ответ проверяется целиком, значит и отдаётся целиком.
- Rate limiting не делали (решение на этапе обсуждения).
- Единица цены (₽ за 1 млн токенов) выведена по порядку величины — документального
  подтверждения в доках Cloud.ru найти не удалось.

### Замечания

- Две настоящие дыры вылезли не на тестах, а на живом прогоне, и обе — в самой защите.
  Первая: заблокированный запрос писался в аудит-лог с ключом открытым текстом,
  потому что функция маскирования трогала только персданные. Гейтвей своими руками
  делал ровно ту утечку, ради которой стоит. Вторая: заблокированное сообщение
  оставалось в истории диалога, и каждый следующий запрос сессии улетал вместе
  с ключом и блокировался — сессия становилась мёртвой. Вывод простой: компонент
  безопасности надо проверять не только «ловит ли», но и «что он сам делает с тем,
  что поймал».
- Разделение «ключи — блок, персданные — маска» оказалось практичным. Блокировать
  email значило бы сломать половину обычных задач, а пропускать живой ключ нельзя:
  он скомпрометирован уже фактом попадания в чужой лог.
- Проверка Луна для карт — дешёвая мера, которая убирает почти все ложные
  срабатывания на длинных числах. Без неё детектор ловил бы номера заказов и
  идентификаторы.
- Два уровня тестов оправдали себя: политика без сети гоняется мгновенно и бесплатно,
  живой прогон ловит то, что видно только на реальном HTTP-пути (формат ответа,
  заголовки, стоимость, поведение агента при блоке).
- Отличие от дня 47: там защита жила внутри агента и зависела от того, как он
  собирает промпт. Здесь она стоит на транспорте и работает для любого клиента —
  хоть curl, хоть чужой скрипт. Это разные слои эшелонированной обороны, и они
  не заменяют друг друга.
