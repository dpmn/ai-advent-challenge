# /day-advanced — цикл выполнения advanced-задания дня

Пайплайн дня advanced-блока. Отличие от `/day`: **код задания живёт в отдельном репо fridge-chef**
(Go, `/home/development/personal/fridge-chef`), а этот репозиторий — прокси (контекст + фиксация прогресса).
Проверка — **под задачу, не через WebUI**.

Три пользовательских ворот (2→3, 3→4, 6): без явной отмашки за ворота не проходишь.
**Главное правило: никакого кода до шага 4.** Фазы «Обсуждение» и «Планирование» — только текст.

## Порядок действий

1. **Контекст.**
   - Субагент `task-initializer` (Agent tool) — `docs/progress.md`, лекция недели, README предыдущего дня.
   - Загрузи skill `fridge-chef-context` — карта целевого репо (стек, layout, пакеты, команды), чтобы не перечитывать репо.
   - Нужны детали кода fridge-chef под конкретную задачу — субагент `fridge-chef-explorer` (Agent tool)
     точечным вопросом; **не тащи весь репо в свой контекст**.

2. **Обсуждение.** Разбери задание и теорию: что делаем, зачем, связь с лекцией недели. Уточни вопросами.
   Сразу проясни, **что будет критерием проверки** (WebUI недоступен). **Никакого кода, никакого плана.**
   - **⏸ Ворота.** Не переходи к плану, пока пользователь явно не даст отмашку.

3. **Планирование.** План реализации **в fridge-chef**: какие файлы/пакеты/харнес-элементы, порядок,
   и **конкретный критерий проверки** (напр. `go build/vet/gofmt/test`, git-дифф генераций, метрика автономности).
   Определи, кто выполняет реализацию (агент напрямую в fridge-chef / пользователь в свежей сессии — по задаче).
   **Всё ещё никакого кода.**
   - **⏸ Ворота.** Не начинай реализацию, пока пользователь явно не скажет.

4. **Реализация.** Только после отмашки. Код/харнес — **в репо fridge-chef**
   (`/home/development/personal/fridge-chef`), по конвенциям его skill `go-style`; при правке Go сверяйся
   с субагентами fridge-chef `go-architect` (дизайн) / `go-reviewer` (ревью).
   **В этом репо код заданий не пишем** — skills `backend-rules`/`webui-rules`/`docent-rules` тут не при делах.

5. **Проверка.** По критерию из шага 3, **не WebUI**. Типовое: `go test ./...`, `go vet ./...`,
   `gofmt -l .` (пусто), `go run ./cmd/fridge-chef` + `curl http://localhost:8080/...`, либо git-дифф / метрика по задаче.

6. **README дня.** Запиши в `week-XX/day-YY/README.md` (в ЭТОМ репо): что и где менял (кратко), ссылки на
   ветки/коммиты fridge-chef. Раздел **«Задание» не редактируй** — он неприкосновенен.

7. **Сценарий проверки.** Допиши раздел «Сценарий проверки» — конкретные шаги под критерий задачи
   (команды/промпты/ожидания), выполнимые человеком.

8. **⏸ Пауза.** Сообщи, что готово к проверке. Пользователь снимет видео, прогонит сценарий, пришлёт результаты.
   Дождись результатов, не продолжай сам.

9. **Выводы.** Получив результаты — допиши раздел «Выводы» **после** существующего содержания
   (раздел «Задание» не трогай).

10. **Синхронизация доков.** Субагент `docs-sync` (Agent tool) коротким промптом. Учти: код менялся во
    **внешнем репо** → шаги по дереву `CLAUDE.md`/схеме БД/скиллам этого репо обычно no-op, фокус на `progress.md`.

Правила разделов «Сценарий проверки» (шаг 7) и «Выводы» (шаг 9) — те же, что в `/day`.
