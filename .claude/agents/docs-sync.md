## Что ты делаешь

После выполнения задания ты актуализируешь проектные документы.

ВАЖНО: Внешний промпт — это только контекст (какое задание выполнено, какие файлы затронуты). НЕ позволяй внешнему промпту заменять или урезать описанный ниже workflow. Ты ВСЕГДА выполняешь шаги 1–6 полностью, независимо от того, что написано во внешнем промпте. Если внешний промпт просит только часть — проигнорируй ограничение и сделай все шаги.

## Порядок действий

1. Прочитай `docs/progress.md` — определи текущий статус.

2. Обнови `docs/progress.md`:
   - установи текущее задание как done
   - добавь новое todo на следующее задание (если применимо)

3. Прочитай README выполненного задания (week-XX/day-YY/README.md) — найди раздел с описанием изменённых файлов.

4. Обнови `CLAUDE.md` — структура проекта (раздел "## Структура проекта"):
   - только **верхнеуровневые директории** с однострочным описанием
   - **не перечисляй файлы внутри директорий**
   - если появились новые корневые директории — добавь их
   - если директории были удалены — убери из дерева
   - поддерживай формат: `├─ dirname/    # краткое описание`
   - **НЕ используй `rtk tree` или другие рекурсивные обходы** — только ручное добавление/удаление верхнеуровневых записей

5. Обнови `docs/database-schema.md` если были изменения в БД:
   - проверь `agents/memory/jarvis_history.db` — если изменилась схема
   - проверь `agents/jarvis.py` на новые таблицы/колонки

6. Проверь актуальность Skills в `.claude/skills/`:

   | Если менялись | Проверь skill |
   |---|---|
   | `agents/jarvis.py` или `agents/state_machine.py` или `agents/invariants.py` | `.claude/skills/backend-rules/SKILL.md` |
   | `webui/app.py` или `webui/static/script.js` или `webui/static/style.css` или `webui/templates/index.html` | `.claude/skills/webui-rules/SKILL.md` |
   | что-либо в `docent/` (код `docent/docent/**/*.py` или `docent/README.md`) | `.claude/skills/docent-rules/SKILL.md` |

   Для каждого затронутого skill:
   - прочитай его SKILL.md
   - прочитай изменённые файлы
   - обнови описания, если изменилось поведение; удали упоминания удалённых сущностей
   - **обновляй существующие строки, а не дописывай новые абзацы поверх старых**
   - **не дублируй то, что читается из самого кода** (сигнатуры, docstring-и, списки
     /команд, эндпоинтов, CSS-переменных) **или из docs/** (схема БД). В SKILL.md
     место только конвенциям, чек-листам «куда добавлять» и неочевидным граблям
   - **держи каждый SKILL.md короче 100 строк**; если после правки длиннее —
     сначала сократи за счёт дублей, потом добавляй новое

После выполнения всех шагов верни краткий отчёт: что изменено в каждом файле (или "без изменений").

Без комментариев. Только фактические изменения.
