# Неделя 6 — День 28. Локальная LLM + RAG

## Задание

**Подключите локальную LLM к вашему RAG-пайплайну:**
- используйте индекс из Недели 5
- retrieval выполняется локально
- генерация ответа — через локальную модель

**Сравните:**
- ответы локальной модели
- ответы облачной модели

**Оцените:**
- качество
- скорость
- стабильность

**Результат:**
- RAG-система, полностью работающая локально

## Что сделано

Весь RAG-путь параметризован по провайдеру: при активной локальной модели эмбеддинг запроса,
FAISS-поиск, реранк, верификация и генерация идут через Ollama — без единого облачного вызова.

- `ragger/embedder.py` — параметры `base_url` и `prefix` (task-префиксы nomic-embed-text:
  `search_document:` при индексации, `search_query:` при поиске); один httpx-клиент на все батчи.
- `ragger/pipeline.py` — флаг `--local`: эмбеддинги через Ollama (`nomic-embed-text`, 768-dim),
  индексы в `ragger/data_local/`. Облачный индекс `ragger/data/` не тронут — оба живут параллельно.
- `ragger/search.py` — `search()` и `RagPipeline` принимают `data_dir` + конфиг эмбеддера
  (`embed_base_url`, `embed_model`, `embed_prefix`, `embed_api_key`); кеш индексов по ключу
  `(data_dir, strategy)`; тайминги этапов (embed/faiss/rerank) в `_last_timings`.
- `ragger/reranker.py` — добавлен `timeout=120` у `urlopen` (мог висеть вечно).
- `ragger/answer.py` — **фикс бага недели 5: в промпт генерации не подставлялся вопрос
  пользователя**. Облачная модель это маскировала (пересказывала найденные документы),
  локальная 7B честно отвечала «Я не знаю». Также при ошибке LLM теперь `confidence="none"`
  вместо пустого ответа с `"low"`.
- `agents/jarvis.py` — атрибут `model_provider` ("cloud"/"local"), хелпер `_rag_provider_kwargs()`
  (выбор индекса, эмбеддера, rerank/verify-моделей под провайдера), сбор `last_rag_debug`
  (провайдер, модели, тайминги этапов, число чанков); RAG-override только при непустом ответе.
- `agents/jarvis_commands.py` — `/rag compare` использует провайдер-конфиг агента.
- `webui/app.py` — `POST /api/settings` выставляет `agent.model_provider`; `POST /api/chat`
  возвращает `rag_debug` и дублирует его в лог Flask.
- `webui/static/script.js`, `style.css` — серая техническая строка под ответом:
  `RAG [local · qwen2.5-coder:7b · emb: nomic-embed-text] embed 0.3s · rerank 11.9s · verify+generate 47.8s · chunks 5 · confidence high`.

По результатам проверки (мешали чистоте эксперимента и давали 404 на локальной модели):
- компрессия истории по умолчанию **выключена** (`agents/jarvis.py`, `jarvis_session.py`);
  новая сессия всегда стартует без компрессии, включение — `/compression on`;
- рабочая память (TaskContext, авто-extraction через LLM после каждого ответа) по умолчанию
  **выключена**: новый флаг `task_memory_enabled`, команды `/task on|off`; при выключенной
  памяти нет ни extraction-вызова, ни инжекции блока в system prompt;
- **строгий режим RAG** (`/rag config strict on|off`, по умолчанию off, персистится в сессии,
  колонка `sessions.rag_strict`) — возврат контракта day-24: при `confidence=none` агент
  отвечает «Я не знаю» вместо fallback-а на основную LLM (fallback давал галлюцинации
  на OOD-вопросах, например выдуманных авторов RAG).

Переиндексация: `python3 ragger/pipeline.py --local` (нужен туннель к Ollama).

Ограничения:
- у nomic-embed-text контекст 2048 токенов — длинные structural-чанки при индексации молча обрезаются;
- порог `threshold=0.2` оставлен: скоры nomic на реальных запросах ~0.65–0.75, порог не мешает;
- первый локальный запрос после простоя медленный: Ollama грузит модель в память
  (Ollama выгружает её через ~5 минут простоя). Таймауты RAG-этапов подняты:
  генерация 300s, реранк 300s, верификация 120s.

### Сценарий проверки

Перед проверкой: поднять туннель к Ollama (порт 11434), запустить `python3 ./webui/app.py`.

1. Открой http://127.0.0.1:5000, создай новую сессию.
2. Отправь: `/rag on`
3. Ожидаемый результат: «✅ RAG-режим включён».
4. Убедись, что в Settings выбрана облачная модель (Qwen/Qwen3-Coder-Next).
5. Отправь запрос: "Какие стратегии чанкинга используются в ragger?"
6. Ожидаемый результат: ответ про две стратегии (fixed-size с перекрытием и structural
   по заголовкам Markdown), блок «📚 Источники» с `ragger/chunking.py`.
7. Проверь серую техническую строку под ответом: `RAG [cloud · Qwen/Qwen3-Coder-Next · emb: openai/text-embedding-3-small] ...`
   с таймингами embed/rerank/verify+generate. Запомни тайминги.
8. В Settings переключи модель на `qwen2.5-coder:7b (local)`.
9. Отправь тот же запрос: "Какие стратегии чанкинга используются в ragger?"
10. Ожидаемый результат: ответ по смыслу тот же (fixed-size + structural), источник `ragger/chunking.py`.
11. Проверь техническую строку: `RAG [local · qwen2.5-coder:7b · emb: nomic-embed-text] ...` —
    провайдер и эмбеддер локальные, тайминги заметно больше облачных (генерация ~30–60 с).
12. Отправь запрос: "Какие таблицы есть в базе данных jarvis?"
13. Ожидаемый результат: ответ на основе документов (sessions, messages, compressed_summaries,
    branches, stage_messages) с источниками; провайдер в техстроке — local.
14. Сравни облачный (шаги 5–7) и локальный (шаги 9–11) прогоны: качество ответа, скорость
    по таймингам, стабильность (нет ли «Я не знаю» / пустых ответов у локалки).
15. Строгий режим: переключись обратно на облачную модель, отправь `/rag config strict on`,
    затем "Сколько лет Юрию Гагарину?"
16. Ожидаемый результат: «Я не знаю…» — без сочинения ответа из общих знаний модели
    (без strict такой OOD-вопрос уходит в основную LLM и она отвечает из общих знаний).

## Выводы

### Что работает
- Полностью локальный RAG-путь: эмбеддинг запроса (nomic-embed-text) → FAISS (data_local/) →
  верификация → генерация (qwen2.5-coder:7b) — все этапы через Ollama, облачных вызовов нет.
- Ответ по базе знаний у локальной модели корректный, с источниками и цитатами
  (вопрос про чанкинг: confidence high, верный источник `ragger/chunking.py`).
- Строгий режим (`/rag config strict on`): OOD-вопрос («Сколько лет Юрию Гагарину?») →
  «Я не знаю» у обеих моделей, галлюцинаций нет. Контракт day-24 восстановлен.
- Техническая строка с таймингами в UI и логах — сравнение стало измеримым.
- Фикс бага недели 5 (вопрос не подставлялся в промпт генерации) улучшил ответы обоих режимов.

### Сравнение локальная vs облачная
- **Качество.** Облако полнее: на вопросе про таблицы БД облачный retrieval нашёл
  docstring `jarvis_session.py` (5 таблиц с колонками), локальный — только старые README
  недели 2 (2 таблицы, неполный ответ). Разница в качестве эмбеддингов:
  text-embedding-3-small (1536-dim) точнее nomic-embed-text (768-dim, 137M) на этом корпусе.
  На простых вопросах (чанкинг) ответы эквивалентны.
- **Скорость.** Генерация: локально 75–104 с против 12–16 с в облаке (~6–8× медленнее,
  7B через туннель). Эмбеддинг запроса: локально на тёплой модели быстрее облака
  (0.3–0.4 с против 0.8–1.9 с), но холодный старт добавляет 9–28 с.
- **Стабильность.** После поднятия таймаутов (генерация 300 с) — стабильно; до этого
  первый запрос падал по таймауту на холодной загрузке модели (~5 мин простоя —
  Ollama выгружает модель). Verify на 7B местами недетерминирован (тот же вопрос —
  то yes, то no).

### Что не работает / требует доработки
- Ответ про таблицы БД неполный у обеих моделей: чанки режутся до 1200 символов в промпте
  генерации (видно по оборванной цитате `CREATE TABLE`), длинные docstring-и теряют хвост.
  Наследие недели 5, кандидат на доработку.
- Локальный retrieval слабее облачного на вопросах, где ответ в длинном техническом чанке;
  вклад дают и 768-dim эмбеддинги, и обрезка чанков под 2048-токенный контекст nomic.

### Замечания
- Fallback на основную LLM при confidence=none оставлен как режим по умолчанию
  (нужен для мета-вопросов), strict — осознанное переключение для анти-галлюцинаций.
- Компрессия и рабочая память отключены по умолчанию — меньше фоновых LLM-вызовов,
  чище эксперимент; рабочая память на локальной модели давала 404 (облачное имя модели).
- Оба прогона шли в режиме threshold (rerank не участвовал); реранк локальной моделью
  проверен отдельно (~12 с на 8 чанков).
