# Неделя 6 — День 30. Локальная LLM как приватный сервис

## Задание

**Разверните локальную LLM как сервис:**
- на VPS или домашнем сервере
- с HTTP API
- с возможностью чата

**Проверьте:**
- доступ к модели по сети
- стабильность при нескольких запросах
- базовые ограничения (rate limit / max context)

**Результат:**
- Приватный AI-сервис на базе локальной LLM

## Что сделано

Вместо деплоя Jarvis (не влезет на слабый VDS) разработан и развёрнут отдельный минимальный
сервис **«Отмазочная»** — генератор отмазок для IT-специалиста (роль × жанр × что провалено),
с чатом для доработки отмазки.

**Где крутится:** VDS 1vCPU / 2GB RAM (Ubuntu 24.04, `ssh finland-vds`), каталог `/opt/excuse-service`,
публичный адрес — `http://2.27.253.165:8080`.

**Архитектура** (docker compose, 2 контейнера):
- `llm` — `ghcr.io/ggml-org/llama.cpp:server`, модель **Qwen2.5-1.5B-Instruct Q4_K_M** (~1GB GGUF,
  качается с HF при первом старте в volume). Ограничения: `--ctx-size 2048`, `--parallel 1`,
  `--threads 1`. Порт наружу не торчит — только внутренняя сеть compose.
- `app` — Flask (Python 3.12), публичный порт 8080: HTML-страница + API.

**Файлы** (в репо `week-06/day-30/service/`, на сервер деплой через `rsync`):
- `docker-compose.yml` — llm + app, healthcheck llm, volume под кэш модели
- `app/app.py` — Flask: `/`, `/health`, `POST /api/excuse`, `POST /api/chat`;
  per-IP rate limit (10 req/мин, in-memory), обрезка входов, cap `max_tokens=200`,
  `repeat_penalty=1.3` (без него 0.5–1.5B зацикливается), few-shot отдельными репликами
  (текстовый пример в system-промпте tiny-модель копировала буквально)
- `app/templates/index.html`, `app/static/style.css`, `app/static/script.js` — страница
  в Claude-стиле проекта: форма (роль/жанр/провал) → отмазка → чат доработки

**Подготовка сервера:** добавлен swap 2GB (файл + fstab) — без него 2GB RAM впритык.

**Замеры:** генерация ~27 с (1 vCPU, ~1GB RAM у llm, swap почти не тронут).
Пробовал Qwen2.5-0.5B (~7 с) — русский заметно хуже, инструкции в чате не держит; выбрал 1.5B.
Нагрузка 12 параллельных запросов: часть обработана по очереди, лишние отбиты 429 (rate limit),
хвост очереди сброшен 503 по таймауту 120 с — сервис не падает, `/health` после нагрузки ok.

**Остановка после записи видео:** `ssh finland-vds 'cd /opt/excuse-service && docker compose down'`.

### Сценарий проверки

1. Открой в браузере `http://2.27.253.165:8080` — страница «Отмазочная».
2. Выбери роль «девопс», жанр «нуар», в поле «Что провалено» введи: `уронил прод в пятницу`.
   Нажми «Отмазаться».
3. Ожидаемый результат: через ~30 секунд появится короткая отмазка от первого лица
   в мрачном тоне (модель маленькая — кривизна текста допустима и является частью шарма).
4. В поле чата под отмазкой отправь: `сделай короче и наглее`.
5. Ожидаемый результат: ответ короче и наглее исходной отмазки — чат работает.
6. Проверка rate limit: открой терминал и выполни 12 раз подряд быстрый запрос:
   ```bash
   for i in $(seq 1 12); do curl -s -o /dev/null -w "%{http_code}\n" --max-time 5 \
     -X POST http://2.27.253.165:8080/api/excuse \
     -H "Content-Type: application/json" -d '{"role":"аналитик","genre":"драма"}' & done; wait
   ```
7. Ожидаемый результат: часть запросов вернёт `429` (лимит 10 req/мин с IP),
   часть оборвётся по `--max-time` (они встали в очередь к LLM) — это нормально.
8. Проверь, что сервис жив после нагрузки: `curl http://2.27.253.165:8080/health` →
   `{"app":"ok","llm":"ok"}`.

## Выводы

### Что работает
- Сервис доступен по сети, полный цикл в браузере: форма → отмазка → чат-доработка.
- Генерация по роли/жанру/провалу: отмазка от первого лица, тема провала учтена
  («прервать беседу ради важных дел» на «не пришёл на созвон с директором»).
- Чат-доработка следует инструкции: на «короче и на сленге гопника» ответ стал короче
  и сменил регистр («Я пойду до свеклы, если твой вариант лучше!»).
- Rate limit: лишние запросы отбиты 429. Принятые в очередь оборвались клиентским
  `--max-time 5` (код 000, Exit 28) — ожидаемо, генерация на 1 vCPU дольше 5 секунд.
- Стабильность: 12 параллельных запросов не уронили сервис, 2GB RAM + swap хватило.

### Что не работает / требует доработки
- Жанр держится слабо: «эпос» дал скорее корпоративную драму без стилистики сказания.
  1.5B-модель понимает инструкцию «жанр», но не тянет стилизацию.
- Хвостовые артефакты генерации: в доработке модель дописала лишнюю строку-инструкцию
  («Напиши отмазки для…») — след few-shot/чат-шаблона. Лечится стоп-последовательностями
  или более сильной моделью.
- Русский местами ломаный («IT-индустрияльной», «совещательному засидке») — потолок 1.5B Q4.
  Для этого сервиса приемлемо (часть шарма), для серьёзной задачи — нет.

### Замечания
- Главный вывод дня: на VDS за копейки (1vCPU/2GB) реально держать приватный LLM-сервис,
  если сузить задачу и модель. Ограничения (rate limit, ctx, max_tokens, таймауты) — не
  формальность, а то, что удерживает слабое железо от захлёбывания.
- Прирост качества 0.5B → 1.5B значительный (следование инструкциям в чате), цена — 7 с → 27 с.
  Для интерактивного сервиса на этом железе 1.5B — верхняя граница разумного.
- После записи видео сервис остановлен (`docker compose down`), данные и модель остались
  в volume — подъём одной командой `docker compose up -d`.
