# Неделя 6 — День 27. Интеграция локальной LLM в приложение

## Задание

**Интегрируйте локальную модель в реальное приложение:**
- CLI-утилита
- телеграм-бот
- веб-приложение
- или другое приложение на ваш выбор

**Сделайте так, чтобы:**
- приложение отправляло запросы в локальную LLM
- получало и отображало ответы
- работало без облачных моделей

**Результат:**
- Приложение, использующее локальную LLM

## Что сделано

Локальная модель `qwen2.5-coder:7b` (Ollama, OpenAI-совместимый API на `localhost:11434/v1`)
встроена в существующий стек Jarvis/WebUI как ещё одна модель в выпадающем списке.
Модель теперь привязана к «провайдеру» — паре `base_url` + `api_key`: облачные модели ходят
в Cloud.ru, локальная — в Ollama. Переключение — обычный выбор модели в дропдауне.

Изменённые файлы:

- `webui/app.py`:
  - карта `MODEL_PROVIDERS` (`model_id → {base_url, api_key}`); локальная модель добавлена
    в `AVAILABLE_MODELS`, её адрес настраивается через env `OLLAMA_BASE_URL`
    (дефолт `http://localhost:11434/v1`), ключ — заглушка `"ollama"`;
  - `POST /api/settings`: при смене модели переключаются `agent.base_url` и `agent.api_key`;
  - `GET /api/models`: добавлено поле `local_models` для пометки локальных моделей во фронте.
- `webui/static/script.js`: локальная модель в дропдауне помечается суффиксом `(local)`.

`agents/` не менялся: весь стек (чат, FSM, сессии, суммаризация памяти) уже читает
`self.base_url`/`self.api_key`, поэтому переключение в одной точке покрывает всё.

Осознанное ограничение: эмбеддинги памяти/RAG остаются облачными
(`openai/text-embedding-3-small` через Cloud.ru) — при срабатывании векторной памяти
запрос за эмбеддингом уйдёт в облако даже при выбранной локальной модели.
Ollama работает на отдельной машине, порт 11434 проброшен на рабочую.

### Сценарий проверки

1. Убедись, что проброс порта Ollama активен (`curl http://localhost:11434/v1/models` отдаёт `qwen2.5-coder:7b`).
2. Запусти WebUI (`python3 ./webui/app.py`), открой http://127.0.0.1:5000
3. Открой сайдбар и посмотри на выпадающий список моделей в Settings.
4. Ожидаемый результат: в списке четыре модели, последняя — `qwen2.5-coder:7b (local)`.
5. Создай новую сессию (кнопка «+»), назови её, например, `local-test`.
6. Выбери в дропдауне `qwen2.5-coder:7b (local)`.
7. Отправь запрос: "Сколько будет 17 * 23? Ответь одним числом."
8. Ожидаемый результат: ответ `391` — сгенерирован локальной моделью (облако не участвует).
9. Отправь запрос: "Напиши функцию на Python, которая проверяет, является ли строка палиндромом."
10. Проверь, что в ответе есть: код функции на Python (def ...), осмысленное решение.
11. Переключи модель обратно на `Qwen/Qwen3-Coder-Next`.
12. Отправь запрос: "Столица Австралии? Ответь одним словом."
13. Ожидаемый результат: ответ `Канберра` — облачная модель работает как раньше.

## Выводы

### Что работает

- Переключение на локальную модель через дропдаун: `qwen2.5-coder:7b (local)` появляется
  в списке, выбор переключает `base_url`/`api_key` агента на Ollama.
- Локальная модель полноценно отвечает через весь стек Jarvis/WebUI: приветствие с учётом
  системного промпта («Я — Jarvis»), арифметика (17 × 24 = 408 — верно), развёрнутое
  объяснение рекурсия vs итерация с корректной таблицей, примерами кода и правильными
  оценками сложности (O(2ⁿ) vs O(n)).
- Обратное переключение на облачную модель — без рестарта, облако работает как раньше.

### Что не работает / требует доработки

- На вопрос «на какой LLM модели ты работаешь?» локалка ответила «GPT-4» — галлюцинация:
  модель не знает, кто она, а в системном промпте идентичность модели не прописана.
  Не баг интеграции; лечится дополнением системного промпта, если это важно.
- В сессии с длинной историей 7B может отвечать невпопад, цепляясь за старый контекст
  (наблюдалось при проверке). Для локалки надёжнее чистые сессии.

### Замечания

- Качество ответов 7B на этих задачах неожиданно достойное — для чата и объяснений
  разница с облаком малозаметна. Основные риски дальше — tool calling (MCP) и длинный контекст.
- Эмбеддинги памяти/RAG остаются облачными — «полностью без облака» выполняется только
  для чат-пайплайна; зафиксировано как осознанное ограничение.
- Интеграция потребовала минимум кода: OpenAI-совместимость Ollama + параметризованный
  `base_url` в агенте сделали задачу конфигурационной, а не архитектурной.
